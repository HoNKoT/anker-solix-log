# Anker Monitor (amon)

Anker のポタ電の **バッテリー残量・入力W・出力W・ポート別の内訳** を、Mac のメニューバーとウィンドウに出し、履歴に残して振り返れる道具一式。
構成は Gradle Queue Monitor (gqm) に倣っています。

```
ポタ電 ──Bluetooth──▶ anker_monitor.py (バックエンド, port 19877) ──▶ ~/.anker-monitor/history.db (履歴)
                         ├─ /status   登録機器の現在値 + ポート内訳 ◀── AnkerMonitor.app (メニューバー) が2秒おきに取得
                         ├─ /history, /ports, /summary  履歴
                         ├─ /api/scan, /api/devices     機器の検索・登録
                         └─ /         ダッシュボード (dashboard.html) ◀── ポップオーバー / ウィンドウ / ブラウザ
```

| 部品 | ファイル | 入る場所 |
|---|---|---|
| バックエンド | `anker_monitor.py` | `~/.anker-monitor/anker_monitor.py` (実行用コピー) |
| ダッシュボード | `dashboard.html` | `~/.anker-monitor/dashboard.html` |
| メニューバーアプリ | `AnkerMonitor.swift`, `Info.plist` | `~/Applications/AnkerMonitor.app` |
| 操作コマンド | `amon` | このフォルダから実行 |
| Python 環境 | (setup が作る) | `~/.anker-monitor/venv` |
| 登録機器・履歴・ログ | (実行時に作られる) | `~/.anker-monitor/` (`devices.json`, `history.db`, `backend.log`) |
| クラウドのログイン情報 | (ログインすると作られる) | `~/.anker-monitor/cloud.json` (自分だけ読める権限 0600) |

実行用のコピーを `~/Documents` の外に置くのは、アプリが Documents 内のファイルを読むたびに macOS が権限を聞いてくるのを避けるためです。

## 入れる

前提: Apple Silicon の macOS、Xcode Command Line Tools (`xcode-select --install`)、Python 3.11 以上 (`brew install python@3.13`)。

```sh
cd ~/Documents/GitHub/anker-ble
chmod +x amon
./amon setup
./amon autostart on     # (任意) ログイン時に自動起動
```

初回は macOS が **「AnkerMonitor が Bluetooth を使おうとしています」** と聞いてきます。「許可」を押してください。出なかった、または拒否した場合は システム設定 > プライバシーとセキュリティ > Bluetooth で AnkerMonitor をオンにします。

## 機器を登録する (ペアリングに相当する操作)

Bluetooth にペアリング操作は要りません。代わりに「探して、見つかった機器を一覧に登録する」手順を踏みます。

1. ポタ電の画面を点け、**スマホの Anker アプリを閉じる** (同時に1台からしか繋げません)
2. メニューバーのアイコンを右クリック → **機器を追加…** (またはダッシュボードの「機器」タブ)
3. **近くの機器を探す** → 見つかった機器の機種を確かめて **追加**
4. 接続には初回 30 秒ほどかかります

「機器」ページでは、登録済みの一覧 (状態・残量)、**名前の変更**、**登録を外す** もできます。登録を外しても履歴は残ります。

## メニューバーのアイコン

機種ごとの形のアイコンを、登録した台数ぶん横に並べます。

- **形**: 液晶画面の位置と全体のフォルムで見分けます。C300 DC は縦長で上寄りに小さな液晶 + 右側のストラップ、C2000 Gen 2 は横長で中央に大きな液晶。ほかは小型 / 中型 / 大型の汎用の形
- **残量**: 下から塗る。50% なら下半分が白、上半分がグレー
- **充電中**: 塗りが緑。**入力があるときだけ**、アイコンのすぐ右に「入力元のマーク + W 数」が出ます (☀ ソーラー、プラグ = AC、⚡ その他)。ソーラーと AC が同時なら2つ並びます。入力が 0W なら何も出ません
- **20% 未満** (充電していないとき): 塗りと輪郭が赤
- **未接続・未取得**: 点線の輪郭だけ
- マウスを乗せると、各機器の `残量・入力W・出力W` がツールチップで出ます
- **残量が 10% 未満** (充電していないとき) になると macOS の通知が出ます。1機器につき1回で、15% 以上に戻るか充電が始まると、また通知できます。メニューの「通知をテスト」で確認できます (通知が許可されていない場合は osascript 経由の通知で代用します)

充電中でも 20% 未満なら赤にしたい場合は、`AnkerMonitor.swift` の `fillColor` の2行の順番を入れ替えて `amon deploy` します。

## ダッシュボード (ページは3つ)

メニューバーのアイコンをクリックすると出るポップオーバー、ウィンドウ、ブラウザで見られます。メニューの「ブラウザで開く」、またはウィンドウ右上の「ブラウザで開く」ボタンで、ブラウザでも同じ画面になります。

| ページ | URL | 中身 |
|---|---|---|
| いま | `http://localhost:19877/` | 機器ごとのカード。最初に出るのはここ |
| 履歴 | `http://localhost:19877/history` | 過去の振り返りと、履歴の容量・削除 |
| 機器 | `http://localhost:19877/devices` | 登録・名前変更・クラウド連携 |

- **いま**: **残量はカード背景の透過した塗り**で、入力・出力は**線グラフ**。表示範囲は「− 直近◯分 ＋」のボタンで 10分 / 15分 / 30分 / 1時間 / 3時間 / 6時間 / 12時間 / 24時間 に増減できます。「ポート内訳」に切り替えると、入力元と出力先ごとの**積み上げグラフ**になります
- **履歴**: 機器と期間を選んで振り返ります。期間は「− ＋」ボタンで 1時間〜365日まで増減でき、チップ (6時間/24時間/7日/30日) や日付指定・◀▶も使えます。グラフにカーソルを当てるとその時刻の値が出ます。期間の電力量 (Wh)、最大・平均、ポートごとの表も出ます
- **ウィンドウに出す**: ポップオーバー左下の「ウィンドウで切り離し」ボタン (右下は「ブラウザで開く」ボタン。どちらも画面の下の操作バーにあるアプリ側のボタンです)で、いま見ているページのまま独立したウィンドウになります (ブラウザとは別。位置とサイズは覚えます)。メニューの「ウィンドウを常に手前に表示」で、他のアプリの上に出しっぱなしにもできます
- **文字サイズ**: 画面右上の **A− / 100% / A+** (または ⌘+ / ⌘− / ⌘0) で、グラフの文字も含めて全体の大きさを変えられます。設定は覚えられます

## 履歴の記録ルール

- 10 秒ごとに記録します。**自動では消えません**
- 「履歴」ページの上に、**履歴のファイルサイズ** (サンプル数・期間・機器ごとの内訳つき) をいつも表示します
- 削除は同じ場所のボタンから、**自分で**行います。「N 日より古いものを削除」(7/30/90/180/365日)、機器ごと、全部、から選べ、実行前に確認が出ます。削除後はファイルも小さくなります (VACUUM)。削除はこの Mac のブラウザ/アプリからのみ実行できます
- 目安: 1行 (1機器・1時点) あたり約 40 バイト。2台を 10 秒間隔で記録すると、1日 約 0.7MB、1年で約 250MB です
- **入力が 0W のときは入力を記録しない**。グラフにも線を描きません (出力と残量は記録します)
- ポート別は **0W より大きいポートだけ** 記録します (記録がない = 0W)
- ポート別の合計が機器の合計入出力より 3W 以上少ないときは「その他」で差を埋めます。内訳は目安として見てください

## 履歴のデータベース (`~/.anker-monitor/history.db`、SQLite)

| テーブル | 中身 |
|---|---|
| `log` | メインのログ。1行 = 1機器の1時点。`dev` (機器の整数ID)、`ts` (UNIX秒)、`pct` 残量、`pin` 入力W、`pout` 出力W、`chg` (0待機/1充電/2放電)、`temp`、そして**内訳の列** (`solar` `ac_in` `ac_out` `dc_out` `usb_c1`… `other_in` `other_out`)。0W は NULL で記録しません。主キーは (`dev`, `ts`) |
| `devices` | 機器の台帳。整数ID、機器ID文字列、名前、機種、接続設定 (BLEアドレス・クラウドのシリアル等、JSON) |
| `log_columns` | `log` の各列が何を指すか (表示名・入力/出力・単位・メモ) |

以前は「合計」と「ポート別」を別の表 (縦持ち、機器IDは長い文字列) に持っていて、1行が約170バイトでした。いまは1行にまとめて機器を整数IDにしたので、**同じ記録で約4分の1** です。古い履歴は、初回起動時に自動で新しい形式へ移ります (数百MBだと少し時間がかかります)。元のファイルは `history.db.v1.bak` として残るので、移行後に中身を確認してから消してください。間引きはしていません (10秒ごとのまま)。

## クラウド (Wi-Fi 経由・外出先からも)

Bluetooth は Mac の近くでしか読めません。Wi-Fi につながったポタ電は、Anker のクラウド (MQTT) 経由で離れた場所からも読めます。**Bluetooth と併用**でき、同じ機器として両方を登録すると、Bluetooth がつながっている間は Bluetooth (速い)、切れたらクラウドに自動で切り替わります。ダッシュボードの「いま」のカードには、いま使っている経路が出ます。

1. `amon cloud-setup` — 部品 (`anker-solix-api`、Python 3.12 以上) を導入。Python が古ければ環境を作り直します
2. ダッシュボードの「機器」タブ > **クラウド** で Anker のメールアドレスとパスワードを入れて「保存して接続」
3. 機器の一覧が出るので、「クラウドのみで追加」するか、登録済みの機器の **クラウドとつなぐ** で同じ機器にひも付けます

注意:
- **パスワードが必要です。** Amazon 等でログインしたアカウントは、Anker アプリの「パスワードを忘れた場合」で先にパスワードを設定してください
- パスワードは `~/.anker-monitor/cloud.json` に平文で保存します (自分だけ読める権限)。Anker のサーバー以外には送りません。この設定は Mac 自身の画面 (localhost) からだけ変えられます
- ログインに失敗し続けるとアカウントが一時ロックされる (エラー100053) ため、パスワード違いのときは自動では再試行しません
- 機器は 2.4GHz の Wi-Fi につないで、Anker アプリで登録済みである必要があります。クラウドからの更新が90秒止まると「オフライン」になります
- クラウドの項目名は `anker-solix-api` のマップに依存します。C2000 Gen 2 (A1783) は対応済みですが、ポート別の内訳が機種によって出ない場合があります

## 操作コマンド

```sh
./amon link          # (1回だけ) どこからでも `amon` で呼べるようにする
./amon status        # 稼働状況と現在値
./amon deploy        # ファイルを変えたあと: 反映してビルド・再起動 (別名: amon up / amon r)
./amon cloud-setup   # クラウドで読む部品を導入
./amon scan-all      # 周りのBluetooth機器を全部表示 (先に amon stop)
./amon logs          # バックエンドのログ
./amon run --debug   # バックエンドを前面で動かして詳細ログを見る
./amon demo          # ダミー機器・ダミー履歴で画面確認 (先に ./amon stop)
```

## うまくいかないとき

| 症状 | 見るところ |
|---|---|
| アイコンが点線のまま | ポタ電の電源ボタンを押して画面を点ける / スマホの Anker アプリを終了。ツールチップに状態が出ます |
| 「接続中」が続く | 初回は暗号化のやり取りで30秒〜1分かかります。`amon logs` で進み具合を確認 |
| 機器が一覧に出ない | 画面を点けてから、もう一度「探す」。すでに接続済みの機器は探索結果に出ません (登録済みの一覧にいます) |
| 点線のアイコンで固まる | `amon status` と `amon logs`。`launch.json` がなければ `amon setup` をやり直す |
| Bluetooth の許可が出ない | 上の「入れる」を参照。`amon deploy` で作り直すと許可が聞き直されることがあります |

## 他の Mac から見る

バックエンドを `--host 0.0.0.0` で起動すると、同じネットワークの別 Mac から `http://<このMacのIP>:19877` で見られます (**認証はありません。自宅/社内LAN内だけで使ってください**。登録や削除の操作も別 Mac からできてしまいます)。外出先で使うなら、持ち歩く Mac で動かして上の「クラウド」で読む形が基本です (自宅の Mac の画面を外から見る仕組みは入れていません)。

## 対応機種

| 機種 | 状態 |
|---|---|
| C300 DC | 動作確認済み (合計の入出力・残量) |
| C300(X) / C800(X) / C1000(X) / C1000 Gen 2 / F2000 / F2600 / F3800 | SolixBLE が対応。Mac 実機では未確認 |
| **C2000 Gen 2** | Bluetooth と Wi-Fi の両方を持っています (FCC 資料)。ただし SolixBLE が未対応のため、Bluetooth は **試験的** (C1000 Gen 2 のクラスを流用) で、機器が一覧に出ない・つながらない可能性があります。**クラウドが本命**です |

### Bluetooth で機器が見つからないとき

`amon stop` のあと `amon scan-all` (またはダッシュボードの「診断」ボタン) で、周りの Bluetooth 機器を全部表示できます。★が付くのは名前に solix / anker を含む、または Anker 共通の広告 UUID を出している機器です。
- ★が出ない → 機器がいま Bluetooth を出していません (画面点灯、スマホの Anker アプリ終了、Mac の Bluetooth 許可を確認)
- ★が出るが「UUID一致: いいえ」 → 機種が違う広告を出しています。そのアドレスと表示を教えてください
- 登録できてもつながらない → SolixBLE のクラスが合っていません。クラウドを使ってください

## 「いま」カードの表示 (v6)

- 電池残量・あと何時間の右端に **IN / OUT の合計** を2行で表示。IN はアイコンで種類 (☀ ソーラー / プラグ AC / ⚡ その他) を区別します。
- その下に **出力の内訳 (1W 以上のみ)**: USB-C1.. / USB-A1.. / DC出力 (シガー) / AC出力。
- **DC出力 (シガー) / AC出力の ON/OFF** をチップで表示します (読み取り専用。操作はしません)。クラウド接続時のみ取得できます。
- **グラフは開閉式** (既定は閉じる)。開閉状態は全カード共通で記憶し、閉じている間は履歴を取得しません。
- 記録が途切れた区間は点線でつなぎます (入力 0W などで値が無いだけの区間はつなぎません)。
- クラウドは 5 秒ごとに状態を要求します。実際の更新間隔は `/api/cloud/raw` の `interval_sec` で確認できます。

## 日ごとの電力量と電気代 (v7)

- 履歴ページの上部に **日ごとの電力量** (入力・出力・ソーラー Wh と節約額) を月単位で表示します。◀ ▶ で月を切り替え、「全機器 / この機器」で絞れます。
- **節約額 = ソーラーで賄えた出力 Wh × 単価** (クレジット方式)。ソーラー入力を Wh のクレジットとして貯め、出力はソーラー分から先に消化します (AC入力が混じっていても同じ)。待機・変換ロス = 入力 − 出力 − 電池の増減 はクレジットから差し引き、電池に入っている量が上限です。電池容量は機種ごとの表 (`MODEL_WH`) から。電気代の単価は画面下の入力欄で変更でき、既定は **39.50 円/kWh** です (`~/.anker-monitor/settings.json` に保存)。
- 1日は、このMacの時刻の 0 時〜24 時。Wh は 10 秒ごとの記録から積算した目安です。
- API: `GET /api/daily?from=&to=&dev=`、`GET/POST /api/settings`。
- グラフの開閉は高さをなめらかに変えるアニメーション (OSの「視差効果を減らす」では即時)。スクロールバーは非表示です (スクロールは可能)。

## 最後のイベントと生データのコピー (v8)

- カードに「最後のイベント HH:MM:SS (N秒前)」と「直近のデータをコピー」を表示します (クラウド接続の機器)。コピーは直近 30 件の生の値 (JSON、シリアルは伏せ済み)。
- `GET /api/cloud/recent?n=` で、直近に届いた生の値を最大 120 件まで取れます。
- ログの「クラウドの生の値」は 5 分おきの出力です (機器の遅れではありません)。値が変わった項目は「クラウドの変化」としてそのつど出します (電力・温度・残り時間は除く)。

## 表示ルールの見直し (v9)

- 出力が無いとき、AC出力/シガーが OFF のときは表示しません (ON になったときだけ、またはポートが 1W 以上のときに出ます)。
- 機器アイコン (カードとメニューバー共通): 入力 > 出力 (1W 以上) は **緑**、出力 > 入力 (1W 以上) は **オレンジ**。USB で出力中は **USB マーク** を重ねます。
- 入力の記号: ソーラーは太陽、AC / USB 給電は稲妻 (電気) マーク。
- 入出力とも 0W のときは「あと何時間」を出さず、「待機中 約 ○W」を表示します。右上の ⓘ に求め方の案内があります (残量 × 電池容量 ÷ 機器の残り時間。実測ではなく目安)。
- ログイン時の自動起動は `amon autostart on` (やめるときは `off`)。

## GitHub で管理して、別の Mac に入れる

### 初回: リポジトリを作って上げる (このMacで)

```bash
cd anker-ble                      # この README があるフォルダ
git init -b main                  # すでに git 管理なら不要
chmod +x amon && git add -A       # amon の実行権限も一緒に記録される
git status                        # cloud.json / history*.db / venv が入っていないことを確認
git commit -m "Anker Monitor"
gh repo create anker-monitor --private --source=. --push   # または GitHub でリポジトリを作って git remote add / git push
```

### 別の Mac に入れる

前提: macOS 12 以上、Xcode Command Line Tools (`xcode-select --install`)、Python 3.12 以上 (`brew install python@3.13`)。

```bash
git clone <リポジトリの URL> anker-monitor && cd anker-monitor
./amon setup           # 環境作成 → 部品導入 (requirements.txt) → アプリをビルド → 起動
./amon link            # (任意) どこからでも amon で呼べるようにする
./amon autostart on    # (任意) ログイン時に自動起動
```

その後の手順 (これらは Mac ごとの設定で、GitHub には載りません):

1. 初回起動で macOS が出す **Bluetooth の許可** と **通知の許可** を「許可」する。
2. ダッシュボードの「機器」タブで **機器を探して登録し直す**。Bluetooth のアドレスは Mac ごとに違うため、登録情報は持ち越せません。
3. Wi-Fi (クラウド) で読む場合は、「機器」タブの「クラウド」で Anker にもう一度ログインする。
4. 履歴 (`~/.anker-monitor/history.db`) は Mac ごとに別です。引き継ぎたいときは、両方の Mac を止めてこのファイルをコピーしてください。

### リポジトリに入るもの / 入らないもの

| 入る (ソース) | 入らない (`~/.anker-monitor` と `.gitignore`) |
|---|---|
| `amon`, `anker_monitor.py`, `dashboard.html`, `AnkerMonitor.swift`, `Info.plist`, `requirements.txt`, `README.md` | Anker のログイン情報 (`cloud.json`)、登録機器 (`devices.json`)、設定、履歴 DB、venv、ログ |

パスやユーザー名はコードに書いていません (`$HOME` と `~/.anker-monitor` だけを使います)。Anker のパスワードは、リポジトリには置かない運用にしてください。

## ウィンドウの拡大縮小・グラフのホバー (v10)

- 切り離したウィンドウは、縁をドラッグして自由に拡大縮小できます (最小 320×400)。
- 「いま」カードのグラフも、マウスを重ねる (スマホはなぞる) とその時点の値 (残量・入力・出力。ポート表示では各ポート) が出ます。
- 過去の記録は、Anker クラウドの API からは取れません (下記)。このアプリが自分で溜めた履歴だけが頼りです。
  - 単体のポータブル電源 (C300 DC / C2000 Gen 2 など、電力システムに入れていない機器) は、履歴や消費量のデータをクラウドへ送っておらず、リアルタイム (MQTT) の値しか取れません。

## スマホから見る (LAN 公開・見るだけ)

```bash
./amon lan on     # 同じ Wi-Fi のスマホから http://<Macの名前>.local:19877 で開ける (URL を表示します)
./amon lan off    # やめる (このMacからだけ)
./amon lan        # いまの状態
```

- 初回は macOS が「python への受信接続を許可しますか」と聞くので「許可」します。
- スマホでは **見るだけ** です。このMac以外からは、Anker のログイン情報・機器の登録・履歴の削除・設定変更の API はすべて 403 で、画面からも隠れます (「機器」タブ、電気代の単価、履歴の削除など)。
- 公開されるのは電力の数値と履歴だけですが、認証はありません。家の Wi-Fi 内だけで使い、ゲスト Wi-Fi やカフェの Wi-Fi では `lan off` にしてください。外出先から見たいときは Tailscale などの VPN を使う方法があります。

### 外出先から見る (Tailscale)

認証なしのまま、ポートを直接インターネットへ公開するのは避けてください。VPN の Tailscale (個人利用は無料) を使うと、自分の端末同士だけで安全につながります。

1. Mac と スマホ の両方に Tailscale を入れて、同じアカウントでログインする。
2. Mac で `./amon lan on` → 表示される「外出先用 URL (Tailscale)」をスマホで開く (`http://100.x.y.z:19877`)。
3. 外出先で見続けるには、Mac を起こしておく必要があります (システム設定 → バッテリー/省エネルギー で、電源接続中はスリープしない設定にする)。

## 履歴の間引きと節電テーブル (v11)

- 履歴 (`log`) は **10 秒ごと** に細かく記録します (履歴画面の「削除…」で 10 / 30 / 60 秒に変更可)。
- 節電の集計は別テーブル `savings` (機器 × 日) に保存します。直近 3 日は 10 分ごとに最新のログから計算し直し、**3 日より古い日は「確定」** として上書きしません。
- 日が変わったら 1 回だけ、確定した日のログ (3 日より前) を **30 秒ごとの平均** に自動で間引きます。精度の要る節電計算は細かいログで終えてから間引くので、ほぼ精度を保ったままサイズを約 1/3 にできます。グラフ表示と電力量 (Wh) は平均でもほぼ変わらず、瞬間のピークだけ丸まります。
- 手動でまとめて間引くには、履歴画面の「間引く…」 (`POST /api/history/compact {"interval":30,"older_than_days":N}`、このMacの画面からだけ)。失敗したときは元に戻ります。
